Move animation glitches in keyed lists

Components with a move hook (componentWillMove, onComponentWillMove, used by inferno-animation) change how keyed lists are patched. Each section reproduces one problem. Animated cards are orange, plain cards are grey. The status line compares what happened with what should happen.

1. Wrong order when animated and plain items move together

Only card 3 is animated. Its move is deferred until the end of the patch, but card 4 is placed right away in front of card 3's old position. The list should read 0 1 4 3 2.

2. Animations measure the list after the update has already changed it

All cards are animated. Moving D to the top and adding X in the same render inserts X before the move hooks run, so inferno-animation takes the "before" positions from a list that already contains X: A, B and C jump one row and then slide one row, instead of sliding two rows, and D starts from the wrong place.

3. A move hook in a nested component crashes the render

The hook to call is chosen by the type of the list item component but taken from the component it renders. Reversing either list throws a TypeError before any card has moved, so the cards keep the old order although the list was rendered reversed.
